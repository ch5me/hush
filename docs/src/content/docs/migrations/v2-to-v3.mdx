# Migrating from Hush v2 to v3

> Historical release note. This page documents an older shipped transition about `hush decrypt` behavior. It is not the current repository migration guide.

## Summary

| | |
|---|---|
| **Who's affected** | Users who were using `hush decrypt` or `hush unsafe:decrypt` |
| **Estimated time** | 5 minutes |
| **Config changes** | None - your `hush.yaml` works unchanged |

<Aside type="tip">
If you were already using `hush run` exclusively, no changes are needed. Just update to v3!
</Aside>

<Aside type="note">
For the current repository migration story, use `hush migrate --from v2 [--cleanup]` and the current docs pages that describe the `.hush/` repository model. This page remains shipped-history context only.
</Aside>

## What Changed

### Changed: `hush decrypt` now requires `--force`

The old `hush decrypt` and `hush unsafe:decrypt` commands have been replaced with `hush decrypt --force`, which:

1. **Requires the `--force` flag** - Won't run without it
2. **Requires interactive confirmation** - Must type "yes" to proceed
3. **Blocks non-TTY environments** - Cannot be run by AI agents or scripts

This makes it much harder to accidentally write plaintext secrets to disk.

### What to Use Instead: `hush run`

The `hush run` command decrypts secrets to memory and injects them as environment variables into your command. Secrets never touch the disk. **This is the recommended approach.**

<Aside type="note">
If you genuinely need plaintext files (Docker builds, legacy tooling), `hush decrypt --force` is still available as a last resort.
</Aside>

## Migration Steps

<Steps>

1. **Find usages of `hush decrypt`**
   
   Search your codebase and scripts for:
   - `hush decrypt`
   - `hush unsafe:decrypt`
   - `npx @chriscode/hush decrypt`
   - `npx @chriscode/hush unsafe:decrypt`

2. **Replace with `hush run`**
   
   | Before (v2) | After (v3) |
   |-------------|------------|
   | `hush decrypt && npm start` | `hush run -- npm start` |
   | `hush decrypt -e production && npm build` | `hush run --target production -- npm build` |
   | `hush decrypt && cd api && wrangler dev` | `hush run -t api -- wrangler dev` |

3. **Update CI/CD pipelines**
   
   If your CI was using `hush decrypt`, update it:
   
   ```yaml
   # Before (v2)
   - run: npx @chriscode/hush decrypt -e production
   - run: npm run build
   
   # After (v3)
   - run: npx @chriscode/hush run --target production -- npm run build
   ```

4. **Update any package.json scripts**
   
   ```json
   {
     "scripts": {
       // Before (v2)
       "dev": "hush decrypt && next dev",
       
       // After (v3)
       "dev": "hush run -- next dev"
     }
   }
   ```

5. **Delete any leftover plaintext files**
   
   If you have plaintext `.env.development`, `.env.production`, or `.dev.vars` files that were generated by `hush decrypt`, you can delete them:
   
   ```bash
   rm -f .env.development .env.production .dev.vars
   rm -f packages/*/.env.* packages/*/.dev.vars
   ```
   
   These files are no longer needed - `hush run` handles everything in memory.

</Steps>

## Configuration Unchanged in that historical release

In that older shipped release, your `hush.yaml` configuration file kept working unchanged.

The `targets` configuration is still used for:
- **`hush run -t <name>`** - Filter secrets for a specific target
- **`hush push`** - Deploy secrets to Cloudflare Workers
- **`hush resolve`** / **`hush trace`** - Debug secret routing

## Benefits of v3

- **Simpler mental model**: Secrets are always encrypted at rest
- **No cleanup needed**: No plaintext files to delete or gitignore
- **Safer CI/CD**: Secrets exist only in process memory
- **AI-safe by default**: No plaintext files for AI to accidentally read

## Getting Help

If you run into issues migrating:

1. Check `hush status` to verify your setup
2. Use `hush inspect` to see what secrets are available
3. Use `hush run -- env | grep YOUR_VAR` to verify secrets are injected

<Aside type="caution">
That statement applied only to the historical release documented here. The current v3 repository model is `.hush/manifest.encrypted` plus `.hush/files/**.encrypted`, and `hush.yaml` is now legacy migration input.
</Aside>
